# adsbtop conventions

The patterns that keep `adsbtop` easy to change. They add to the repo-wide [CONVENTIONS.md](../../CONVENTIONS.md), whose cross-cutting rules (TSDoc, naming, unit suffixes, code style, ESLint) apply here too; this file covers only what is specific to this app. For what the app does and how to run it, see its [README](README.md).

The app is Ink and React 19 drawing into a terminal, with `ink-text-input` behind the search and filter prompts and `ink-testing-library` behind most specs. Unlike the browser-side apps, this package extends `tsconfig.base.json` and adds only `rootDir`, `outDir` and `jsx`, so `exactOptionalPropertyTypes` and `noUncheckedIndexedAccess` are on and several rules below depend on the first of those.

## State and rendering

`App` owns every piece of display state and every key binding. The components under `src/components/` are presentational and hold none of their own. The feed, the registry, the terminal's size and the bell each live in a `use-*` hook beside `App`, and everything else is a plain module `App` calls.

- **Display state is corrected during render, never synced by an effect.** Anything render already has what it needs to derive - the paused table's frozen rows, the sort key when its column stops being visible, the cursor row, a panel's window start - is fixed by a guarded compare-then-set at the top level of `App`, which React re-runs before it paints. Reaching for a `useEffect` to keep one of those in step is the reflex to resist: it commits an extra frame, and `react-hooks/set-state-in-effect` is an error in this package. The comparison guard is what keeps the render-time form legal, since `react-hooks/set-state-in-render` is an error too. Effects are left to subscriptions and timers.
- **State the clock tick re-renders must keep its reference when nothing has changed.** The reducer replaces its aircraft map only on a real event, and the aircraft array is memoized on that map reference, because the pause freeze compares those references directly and every consumer has the array in a dependency list. Derive a fresh array or object per render instead and the compare-then-set fires every frame while every memo and effect downstream sees a change once a second.
- **One clock drives everything on screen, and it arrives as an explicit `nowMs`.** `App` ticks once a second and passes the timestamp down; nothing below it reads the clock for display. That is what keeps the age column, the stale dimming, the uptime line and a `[W]` snapshot consistent within a frame, and it leaves each of those modules a pure function a spec can pin to a fixed timestamp - a `Date.now()` inside a formatter quietly breaks both. A `Date.now()` at the moment of an event is a different thing and stays where the event is: the `at` on a dispatch, a notice's timestamp, the snapshot filename.
- **What is tracked and what is shown are different values, and each consumer is handed the one it needs.** The chain runs from the feed's own list through registration enrichment to the pause-frozen copy, then sort, then filter. The cursor, search, the detail view and the `[W]` snapshot all read the filtered list, so a hidden aircraft can never be selected or exported.
- **Two bypasses of that filter are deliberate, and each is documented where it happens.** Watchlist and emergency alerts diff the unfiltered tracked list, because the bell is about what is tracked rather than what is on screen, and `--record` subscribes to the feed directly so the file holds raw events instead of the enriched view. Routing either through the filter compiles, looks right on screen, and makes the bell lie.
- **Every global key is handled in `App`; a component never calls `useInput`.** One handler owns the keymap and deactivates itself while the search or filter prompt is open, so a character typed into a prompt cannot also fire a hotkey; a second handler, active for exactly that state, adds nothing but the `Escape` that `ink-text-input` has no cancel key for. Omit or widen either handler's `isActive` and typing `q` into the search box quits the app.
- **A new hotkey means editing several hand-kept lists in the same change:** the `switch` in `App`, the hotkey bar, the help overlay's entries, the README's hotkey table, and the column picker's own legend when the key belongs to the picker. Nothing ties them together - no compile error, no failing spec - so an omission ships as a key the user cannot discover, or a label for a key that no longer does that.

## Ink and the terminal

Ink lays out with flexbox and repaints the whole tree on every state change, into a grid of cells it does not own. The rules below all fall out of that: it cannot take back a line the terminal has already scrolled away, it shrinks a row's children to make them fit, and anything else writing to the same stream lands in the middle of its frame.

- **The terminal's height is a budget, and a panel that overflows renders a window rather than letting output scroll off.** Which contract a new panel follows depends on where it sits. A fixed-height panel below the main one exports a height function beside its component and gets its own field on `MainPanelBudget` for the row budget to subtract; a main panel takes a `RowWindow` prop and renders that slice. `viewport.ts` holds the row constants, the budget shape and the window planner: a fixed-height panel adds a field there, a main panel reuses `planWindow` from `App`. The terminal's own scrollback is no help here, so a panel that skips the budget silently pushes the bottom border off the screen.
- **A terminal that reports no height windows nothing at all.** The `undefined` travels from the terminal-size hook through the row budget to a window of infinite rows, rather than being guessed at the way a missing width falls back to 80 columns. Substituting a default height there would make every non-TTY render, the test harness included, silently clip its output.
- **When a row overflows, Ink shrinks whatever shares it.** Content that can wrap gets its own row, or sits beside content pinned with `flexShrink={0}`: the status bar's chips moved to a second line for exactly this reason, and a table row's last cell carries no trailing margin, since the extra column pushes the row past the table's inner width and Ink pays for it by truncating the first cell. Adding chrome beside a wrapping label eats the label's letters instead of erroring. The table's own frame width is a constant kept in step with its outer `Box` by hand.
- **A band whose height depends on wrapping reserves its rows as a constant rather than measuring them.** The hotkey bar is two rows in the budget because its labels change with state and it wraps below roughly 120 columns; one wasted row on a wide terminal beats a clipped bottom border on a narrow one.
- **Ink's own style props are never passed as `undefined`.** `exactOptionalPropertyTypes` is on and Ink types `color`, `backgroundColor` and `bold` as plain optionals, so `backgroundColor={selected ? 'cyan' : undefined}` does not compile. The fix is not a cast or a `?? ''`: branch the whole element, as the cursor row, the active sort header and the notice chip each do, or build a style object holding only the props that apply and spread it, the way `row-style.ts` does.
- **A component's data props are the opposite case.** They are declared as required `T | undefined` rather than optional, so a caller can pass undefined across a boundary the app owns without a branch. Declared optional, a caller holding `cond ? value : undefined` could not pass it at all - the same `exactOptionalPropertyTypes` rule, now working against the app's own boundaries. The one exception is an injected collaborator, which is optional so its production default can apply at the use site.
- **Dark text on a colored background is written as `#000000`, never the named ANSI `black`.** `black` is the obvious spelling and the wrong one: it routes through the terminal's own customizable 16-color palette, and many themes remap that slot to a soft gray, indistinguishable from black on a default background and plainly gray on a bright one. Bold is a separate judgement rather than a ban - the active sort header leaves it off because bold in a base ANSI color commonly renders as that color's bright variant, while bold white on the blue bars and bold red on the cyan cursor row are both deliberate.
- **Nothing writes to the terminal while Ink is rendering.** A `console.log` or a raw `process.stdout.write` corrupts the frame rather than merely adding a line, and no lint rule catches it. A failure becomes a status-bar notice instead: a failed `--record` open and a failed `[W]` snapshot both set one, and argument errors are written by the CLI before `render()` is ever reached. `ringTerminalBell` is the sanctioned exception and explains itself - BEL is zero-width so a raw write moves nothing, while routing it through Ink would clear and redraw the app to insert a line - so do not read it as licence to write anything else.

## Columns

- **A new table column is a fixed checklist inside `columns.ts`:** its key in the `ColumnKey` union, its entry in `COLUMNS`, a slot in `AUTO_FIT_DROP_ORDER`, and a `sortValue` case that mirrors what `render` produces. The sort case is the step nothing catches - that switch ends in a `default` returning undefined, so a missed key compiles, passes the suite, and silently orders every aircraft as though it had no value for that column. The drop order the README spells out is a hand-kept copy of the same list and moves with it. Leave a column out of the drop order only when it must never be dropped, as the ICAO hex is.
- **A column the session cannot populate is unavailable, not merely hidden.** Set `requiresLocation: true`, or name the source in `unsupportedSources`, and let the consumers react: it is dropped before anything else runs, so it is absent from the table, from the `[C]` picker's selectable rows, from `[A]`, and from the sort keys, and `--columns` naming it fails at startup with a message instead of rendering a column of dashes. The reason is one string phrased as a predicate (`needs --lat/--lon`, `is not sent by sbs`) so the same text reads correctly both dimmed below the picker's rows and inside the CLI error. A hidden column, by contrast, is still available - the picker can toggle it back on.

## Reaching outside the process

- **Anything that reaches outside the process is injected, with the production implementation as the default.** The tempting move when adding an outside-world touch is to import the real thing and call it, which makes the calling code untestable. Instead the collaborator arrives as an optional prop or a defaulted trailing parameter that resolves to the real implementation at its use site, or, where no single default makes sense at that layer, as a required field the layer above fills in. The payoff is that a spec drives the whole dashboard with no socket, no disk write, no terminal bell and no registry dataset.
- **`run()` returns an exit code and the entry point assigns it.** `n/no-process-exit` is an error in this package's own ESLint config, and exiting mid-frame would cut the terminal restore short as well as the output.
- **The bundled registry loads after mount, never at import, and a failed load degrades to `-`.** Decompressing and parsing the dataset would otherwise sit in front of the first paint, so it arrives through a dynamic `import()` from an effect behind a cancelled flag - which also constrains where the import for any future bundled dataset may go. Two things here read as defects and are not: the empty catch is deliberate, since a registration is enrichment and a live dashboard is worth more than its N-numbers, and the enrichment cache stores a resolved miss as `undefined` so a hex the registry does not know is not looked up again on every render.
- **Anything that grows with elapsed time or event volume carries an explicit cap.** A session runs for hours, so the message log is trimmed to `MAX_MESSAGE_LOG_ENTRIES`, the rate sparkline keeps the last `RATE_HISTORY_LENGTH` samples, and the feed is handed a `POSITION_HISTORY_RETENTION` bound even though adsbtop does not read that history. What grows with the number of distinct aircraft instead - the registration cache, the session's seen-hex set - is uncapped on purpose, because one small entry per aircraft is already bounded by real traffic, so do not "fix" one.
- **`src/cli.ts` sets `NODE_ENV` and only then loads the app, through a dynamic `import()`.** React picks its build on first import, and its development build records a `performance.measure()` entry per render that Node never evicts. A static import hoists above the assignment, so converting that line back to a normal import looks like tidying and reintroduces an unbounded leak.

## Tests

- **Two spec harnesses, and the choice matters.** `ink-testing-library`'s `render` is the default, but the stdout it fakes reports a fixed 100 columns and no height at all, so a spec that exercises the row budget renders through Ink's own `render` against the hand-rolled sized stdout in `app-viewport.spec.tsx` (with `debug: true`, which is what makes the frame capturable), adding its fake stdin when it also has to send keys. Reuse those and the fakes in `test-utils.ts` rather than re-rolling them.
- **Assertions are substring checks on the last frame, and that frame carries no color codes.** Ink colors through chalk, which emits none when the test process's stdout is not a terminal, so a color, a background or a bold is never assertable - assert the content that branch renders instead. Keys go in as raw bytes, escape sequences included.
- **A render that keeps something alive is unmounted after the test.** The clock interval, a feed subscription and a pending dataset load all outlive the assertion and leak into the next test; a plain component render has nothing to clean up and needs no `afterEach`.
